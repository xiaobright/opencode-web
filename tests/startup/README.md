# 按需启动与自动休眠验证

- `bun test ./backend.test.mjs ./cli.test.mjs`：服务启动合并、失败重试、探活/静态文件/API 不启动后台、启动接口的同源限制、代理保留鉴权和页面注入、默认模式兼容，以及真实 `src/start.mjs --lazy` 入口和重复启动。CLI 使用隔离目录和不存在的后台可执行文件，未调用真实服务。
- `bun test ./idle.test.mjs`：自动休眠的判定与接线。空闲时长/开关的环境变量、三信号（无请求、无事件流、无会话活跃）逐项keep/sleep 判定；扫掠停止服务后相位清零、再次请求重新拉起；窗口内被用过的共享服务不被停；托盘 2 秒探活不计为活动、普通请求计为活动；关闭休眠时元数据不出现 `autoSleep`。全部走注入的服务夹具，不触碰真实 CLI。
- `bun test ./models.test.mjs`：免费模型筛选（免费、启用、支持工具）与排序/钉死/回落；排序文件读写与去重；网关 `GET/POST /__opencode-web/models` 的目录、保存、同源校验和非法请求。状态目录用临时夹具，不碰真实排序。
- `bun run run.mjs`：浏览器先显示 OpenCode 标识与加载状态、后台未就绪时页面可见、多个页共用启动、保留会话深链接、失败后手动重试。使用模拟后台，不调用真实模型。
- `pwsh -NoProfile -File tray-policy.ps1`：从实际托盘脚本提取状态处理函数，确认待用模式始终显示图标且不探测后台；默认模式服务缺席时（自动休眠）图标常驻并显示「待用，点击启动」，不自行退出。此项不创建真实托盘图标。

本次逻辑/CLI 测试、浏览器检查和托盘状态策略检查通过。加载画面截图和 CLI 临时目录保存在忽略的 `test-results/`、`.cache/`。

未自动设置开机自启；未通过真实托盘点击启动用户的 OpenCode 服务。实际启动/停止服务仍复用原有的 `service.mjs`，执行 `opencode service start` / `opencode service stop` 后等待健康注册。休眠扫掠对服务的停止经过 `backend.stop()` 注入通道，测试夹具不会到达真实 CLI（早期版本直接 import 曾误停真实服务，回归测试即为此而写）。
