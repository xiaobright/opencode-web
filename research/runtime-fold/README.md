# 执行前补丁路线研究（2026-10-17）

结论：中间路线在当前安装版本上可行。仅修改官方发布脚本的一处入口，就能在生成时间线行时折叠已完成过程，并响应展开操作；再修改一处挂载范围，对少量已加载行提前渲染测量，本次历史滚动实验的额外位移降到 0。这是有限条件下的原型结果，不是全场景无抖动承诺。

本目录是隔离研究原型，**没有接入 `src/`、`webui/` 或托盘**。当前正式入口保持无二次折叠。没有修改上游源码，没有重启后台，没有调用模型。实验代理仅从现有后台读取静态资源；所有 `/api`、`/auth` 和非 GET/HEAD 请求都在代理处阻断，测试由官方夹具提供模拟会话。

## 实际改了哪两处

第一处将发布模块中的 `e.constructSessionMessageRows=t;` 接到一个包装函数。包装函数仍先执行官方投影，再从结果中排除已完成轮次最终正文之前的普通 `AssistantPart` 行；展开时返回原行对象。它位于官方行索引、行键和虚拟列表计算之前，所以不需要用 CSS 把行压成 0，也不修改服务端消息。

原型直接使用该模块已有的 Solid signal，使按钮操作触发官方响应式重算。全展开、全收起和指定单轮切换均已验证。控件暂放在独立实验面板内，没有实现答案上方的“用时”入口。正在运行、消息未完成、出错或工具未结束的轮次保持展开。压缩通知、独立 Shell、轮末 diff 等特殊行不纳入此原型的折叠。

第二处是可选的 `eager` 模式：在官方正常挂载范围计算处，当投影后的行数不超过 300 时挂载全部已加载行，让布局测量提前完成；超过 300 行仍使用原来的虚拟化。**没有取消官方的布局与滚动代码，也没有更改滚动补偿判据。**

300 是实验边界，不是已论证的安全阈值。一行可能包含非常大的 Markdown 或 diff，行数上限并不能保证计算量、内存上限。

## 实测结果

夹具为 60 轮已完成会话，每轮包括用户消息、途中说明、读取工具和最终正文。视口 1280×700；先上滚 1800px 离开底部，再连续做 10 次 320px 上滚。比较前后都可见的同一行，计算其屏幕位移与 320px 的差。使用真实浏览器 wheel 输入和 `scrollend` 完成信号；eager 模式开始前还确认全部行已挂载、行盒高度与内容测量一致。

| 模式 | 最大额外位移 | 初始挂载行数 | 当前 DOM 元素数 | JS 堆快照 | 就绪检查耗时 |
|---|---:|---:|---:|---:|---:|
| 官方原样 | 83px | 8 | 770 | 20.4MB | 1.19s |
| 仅投影折叠 | 185px | 7 | 812 | 21.0MB | 1.03s |
| 投影折叠＋有限全部挂载 | **0px** | **179** | 3343 | 54.1MB | 2.04s |

这些是本机样本值。就绪检查耗时含夹具准备和页面加载，不是严格的产品首屏性能指标；堆用量不是浏览器进程总内存，并受 GC 时机影响。三种模式紧凑度不同，同样滚动距离看到的行也不同，不能把这张表当成通用性能排名。

eager 模式独立跑过两轮滚动实验，均为 0px；后一轮 34 个前后都可见的行样本均无额外位移，每次实际 scrollTop 差均为 320px，内容总高不再变化。它证明的是**这个已加载、已测量的历史场景**，并不证明每一个合成器帧都没有闪动。

其他验收：

- 已完成会话：4 行变 2 行；过程中间文字从 DOM 中消失；展开后文字和原生工具入口恢复，再收起、单轮展开均正常。
- 进行中的轮次：过程说明和正文保持可见。
- 120 轮样本：折叠后 359 行，确认回退为少量行挂载的虚拟列表；超过边界后不再承诺消除滚动漂移。
- 未知脚本指纹：不注入运行时、不修改候选脚本；浏览器正常显示官方页面。已完成和进行中两项均通过。
- 单元检查：5 通过，覆盖补丁语法、原始字节回退、原消息不变、原行身份恢复，以及 busy/error/running 情况保持展开。

## 升级与维护边界

补丁要求整份模块 SHA-256 已知，并且函数赋值、signal 引用及可选挂载范围均唯一匹配。短变量名由结构匹配提取，不硬编码为某个压缩变量。

现在只准许上面这一份已验证的发布资源。即使将来只是无关代码变化，也会保守地停用折叠，继续显示官方 UI；不能声称已经实现跨版本自动适配。升级后的工作是重新获取资源、检查结构和行为、验证后增加支持指纹。采用更宽松的匹配可以减少维护，但误改风险需要另外验证。

已验证的回退是**资源不匹配时的回退**。这不等于所有浏览器运行时异常、资源加载失败都已有自动恢复机制。

## 目前不能承诺的部分

- 初次加载期间、流式结束转为折叠的瞬间，以及正在滚动时展开或收起的视觉连续性。
- 历史分页追加、会话切换与恢复、设置切换、深链接定位隐藏工具、多窗口状态、移动端。
- 大 diff、长 Markdown、图片或附件、字体和窗口宽度变化的性能与稳定性。
- 展开使行数跨过 300 的阈值时，挂载策略切换的体验。
- 原型只折叠最后正文之前的普通过程行；仍需决定和实现特殊通知、压缩、失败轮次的产品行为。

因此适合继续做“少量已加载历史优先稳定”的实验版本；若要求超长会话、所有更新过程都平滑，仍需要更完整的测量缓存/锚定设计或上游修复。没有证据要求重写整个前端，但也不能把两个补丁当作完成品。

## 复现

在 `E:\Desktop\mytests\opencode-web` 执行，需要官方后台已经运行、参考源码已有依赖。原型不会帮忙启动后台或安装依赖。依赖位置可通过 `OPENCODE_SOURCE` 覆盖。

```powershell
bun run research/runtime-fold/inspect.mjs
$env:OCW_RESEARCH_MODE = 'eager' # baseline / patched / eager / incompatible
$env:OCW_RESEARCH_RUN = 'eager-new-run' # 使用新名字，保留旧实验记录
bun run research/runtime-fold/run.mjs
```

单元检查在 `research\runtime-fold` 目录运行：

```powershell
bun test ./patch.test.mjs ./project.test.mjs
```

`run.mjs` 由 Playwright 启动并收回独立的 53124 端口实验代理；浏览器使用隔离的临时上下文。手动打开实验代理不能当作普通客户端使用，因为真实 API 被阻断。

`inspect.mjs` 获取当前发布脚本，`patch.mjs` 做已知版本补丁，`project.mjs` 处理行列表，`runtime.js` 提供实验控制，`server.mjs` 验证静态资源代理链路。正式入口没有引用其中任何文件。
